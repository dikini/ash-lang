# Same-build checked helper provenance — early verification

This product slice starts from retained PR112 `8b844436` under
[TASK-0053](../../../TASK-0053-checked-owner-core-execution.md). It connects an
actual helper/header/ABI build transaction to the existing private checked
producer and ReceiptSeed. It is not a new registry or approval mechanism.

The transaction derives C prototype assertions from the authenticated target
bridge plans. A generated ABI context is force-included while discovering and
compiling the actual helper definitions. Discovery observes the complete emitted
include set; those regular files and the original/copied helper/header bytes are
then pinned and revalidated around syntax/object/archive work. Actual dependency
sets must match discovery. This is conditional observation/revalidation of
canonical paths, not immutable header snapshots or a pre-query header history.

Compiler queries, fixed compiler environment, generated ABI assertions, command
arguments/output pins, object/archive and tool observations form owned sidecar
data. The final producer binds that sidecar into BuildConfiguration together
with actual image/facts/original/archive/policy associations. Whole native,
header, tool and runtime closure, independent premises and protected context
remain Missing. A queried cc1/search path or runtime fingerprint is not proof
of all compiler subprocess, CRT, allocator or standard-library inputs. Prebuilt
archives keep their existing unproven classification. Matching data cannot
activate execution; public build/binding/initializer/report guards stay closed.
