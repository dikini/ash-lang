# Private family specialization helper draft

This is source-only preparation for the selected A-0 scalar experiment. It is not current Ash semantics or a verified implementation. No compiler, formatter, tests, or other engines were run; no actual repository source was edited by this assignment.

`helpers.rs` is intended for insertion into `src/core/provider/specialization.rs`, so its private same-module helper references resolve there. It uses the parent's existing `SpecializedDictionary` definition. `certificate-getter.rs` is the required additive original-token reader in `impl CheckedProviderContracts` in `src/elaborate/provider.rs`; the owning writer must compose it. There is no metadata-only fallback if that original family certificate is absent.

Call `authenticate_family_header` first for the exact admission/member/copy/registry/renaming inputs, then call `authenticate_family_dictionaries` with those same inputs. The header returns the original certificate's independently substituted provided effect. Use this exact effect in the grouped row/capture checks and final attached-handler instance check. Hidden answer/row equations, exact substitution-map domains, disjoint freshening, complete copied node/projection/catalog admission, and actual selected method-vector/forwarding identity remain the enclosing admission's existing responsibilities.

The dictionary helper supports only the sealed native Layout interface, its one canonical method, and Unit/Bool/Int dictionaries. Any other prerequisite category is refused. It borrows the original certificate's ordered checked requirements and the original template's ordered dictionary formals. It checks the original template against the exact family handler certificate token, not just against matching header fields.

Each prerequisite locator must be earlier than the uniquely matched ProviderFamily node in the same immutable plan. The family may be a prerequisite under an Implementation root; the helper retains the original whole-plan root and never treats its application as the family or Layout goal. Matching uses the exact source identity, complete family application and ordered same-plan prerequisite locators. The canonical Layout goal is independently substituted from the original requirement. The helper checks the native producer and dictionary's interface, method, witness, exact payload type, scalar encoding, size, and alignment, then checks the copied binder's exact original projection and actual intrinsic initializer/type.

The resulting `SpecializedDictionary.projection.node` is the mapped original template root, used as the projection's reference coordinate. During final reauthentication, compare the actual ordinary Let binder using `project_binder(expected.projection.node, binding.binder(), work)`; do not replace that reference coordinate with the Let node. `initializer.node` is the actual initializer node. Final admission must find exactly one ordinary Bind declaring each expected binder, require that exact initializer, compare both stored projections and the canonical producer, and use ordinary whole-Core scope validation to establish domination of the owning ProviderScope. A parameter, recursive binding, state binder, unrelated dictionary, or a type-correct alias is not that original dictionary binding.

Copied source Abstract selection identity and provenance remain unchanged, apart from the existing simultaneous type/row specialization. The outer Let supplies its selected native dictionary. Do not replace the original Abstract node with counterfeit NativeLayout or Lexical evidence. Final family method-scope lookup must consume the admitted original-formal-position to copied-binder mapping and the authenticated initializer link.

Remaining integration dependencies are the additive certificate reader, same-input header-before-dictionary call ordering, enclosing admission obligations above, and final ordinary-Let uniqueness/domination and family method-scope reauthentication. No further source composition is authorized by this frozen draft.
