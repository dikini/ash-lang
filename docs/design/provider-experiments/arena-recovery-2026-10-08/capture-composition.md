# Private scalar capture composition candidate

This source-only candidate is based on Arena commit `dbe34ed2cbd96e6e50708034b9dddda4eb66a112`. It is experimental preparation, not language authority or verification evidence. Common/Fusion owns composition onto a verified capture successor. No actual capture or type file was edited. No engine, test, or formatter ran.

`capture-scalar-candidate.patch` replaces the earlier rejection-only draft in `candidate/`. The historical `capture-enum-closure.patch` remains a separate earlier checkpoint and is not the current proposal. `candidate-pins.json` pins the committed baseline and current three candidate files.

## Implemented private relations

- `selection_targets` authenticates a native scalar producer against the original registry dictionary table and retains its complete producer header. A new explicit family callback receives the selection, exact node and method; it must authenticate the original family certificate, full ordered goal, prerequisites and exact forwarding binder. Family prerequisites are traversed by the existing iterative postorder worklist. Neither a spelling nor a scalar tag grants authority.
- Canonical native Layout evidence becomes an independent callable returning metadata. Direct intrinsic nodes require the same full admitted producer and exact producer type. The producer may arrive directly or through an implementation prerequisite. The independent-callable atom completes calls without inventing a source closure/control target. Reference values never use this path.
- Every attached handler clause is retained in source order, every member state binds to the same resource handle, and the handler port walks the actual finite binding chain. Additional Type/Row headers and complete family goal arguments participate in metadata retention.
- One handler control boundary carries the finite provided/native member inventory and flat clause-to-member index. Selecting any member removes the entire group. Native selection finds the nearest relevant group phase: an active or resumed body handler denies clause permission, while a selected clause permits only its own complete native instance. One enclosing resource occurrence remains live. Lifecycle execution outside the group retains the outer native interpreter. Legacy one-member scopes retain their original representation and paid traversal structure.
- A grouped scope consumes only specialization-authenticated native receipts. Receipt installation rechecks copied Request identity/operation/full effect, exact owner and family/member coordinates, and canonical Store/Load constructors. It walks receipt records rather than adding a scan of legacy nodes. The parent-provided generic projection authenticator is a required composition dependency, not replaced by trusting a raw descriptor field.
- Store creates both canonical result alternatives. Its success projection yields a distinct nonowning `Reference(owner, creation)` atom; refusal projects independent error data. Returning the whole result, its reference, or a closure/aggregate retaining either carries the exact owner dependency. A reference cannot satisfy a State operand.
- Load requires the actual state atom and actual reference atom to name the same live owner occurrence before its scalar result becomes independent. The sealed original/copy relation separately establishes the complete payload/witness signature. Native responses cannot use the escaped-request scalar shortcut. Ambiguous native labels fail closed.

All new scratch vectors use fallible reservation and explicit work debits. Added graph ownership consists of flat indices or shared immutable effect metadata; no recursive runtime environments or native owner keepalive are introduced. Private physical allocation identities remain runtime responsibilities.

4. Unclassified requests retain the old conservative fallback and cannot establish the new positive gate.
5. Format and compile only in the coordinated engine window; this packet has no compile, borrow-check, test, baseline-cost or semantic-pass claim. In particular, the generic receipt helper is still a parent-owned evolving API.

## First connected gate and exclusions

The current `arena.ash` family clauses use match, native Store/Load and Resume without discard. `CheckedHandlerTemplate::needs_actual_captures()` is exactly whether its row recipe contains discard records, so the first scalar fixture should not require actual capture-row inputs. This does not justify empty capture inputs for a later discard-sensitive family.

Use allocation41/load41 as the first positive and require Stored then Loaded with matching activation/allocation/layout, unchanged usage on load and one release. Follow with zero-size distinct IDs, prior-object reads after refusals, a source override refusal with no native Store, and exact escaped/wrong-owner/fabricated authority rejection. Native minimum/lower-overflow evidence remains separate from source upper-overflow because source negative literals are intentionally unsupported.

The candidate targets authenticated finite Unit/Bool/Int families. It adds no arbitrary payload codec, Ref-containing stored payload contract, recursive layout policy, new source authority, or general discard-family capture-row solver. Its group cleanup/restoration paths and finite-context reference propagation still require connected composition verification.
