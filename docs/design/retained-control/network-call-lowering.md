# Structural network call lowering

This is an implementation design for the accepted [CP-0027](../../proposals/CP-0027-pinned-workers-and-copied-channels.md) and [AD-0017](../../decisions/AD-0017-pinned-worker-host-and-transport.md). It grants no completion or release permission. The one-way completion cut and its separate proof assignment remain required.

The current request-based precursor is incomplete. In a worker-local `region` and `using` scope, source capture inference treats the network IO request as an unknown outward handler that can retain the local continuation. Moreover, re-executing an initializer's allocation-context query only in the evaluator would introduce control that the linked Core graph does not contain. Selecting the worker entry region directly also ignores a nested selected provider.

## Source and Core

Keep the source-visible functions and rows from CP-0027. Direct source `perform`, `handle`, hook and registration of `Network.IO` and `Network.Join` stay sealed. The canonical checked built-in function definitions are nominations for compiler lowering; spelling, a source span, or a nominal type alone confers no authority.

Lower each supported canonical wrapper to an ordinary polymorphic function whose body first evaluates the existing default-allocation context query and then a dedicated structural network call. The call has explicit Core children for that selected `RegionView` and the wrapper's parameter projection, plus the exact network module, operation kind and N instance. Its result type and effects are reconstructed from the canonical checked registry, its actual operand, and the existing allocation row. Result constructors and envelope provenance come from the authenticated registry and transport; application bytes cannot select a control envelope. Ordinary strict application evaluates the source function and argument before entering the wrapper. Inside the wrapper, the query runs first, the already bound parameter is projected once, and only then may the host transition occur.

The structural call specifies its result allocation and possible control paths. For send, those paths include one result allocation on `Sent`, `Full` or `Closed`, and the failure value plus result allocations on a reported failure. An accepted send remains accepted if its later result allocation refuses or reenters. For receive, they include one result allocation for `Empty` or genuine `End`, failure and result allocations on failure, and receiver bytes, envelope kind, payload tuple and `Message` allocations on a delivery. If the final commit or held-obligation reservation refuses after those four allocations, two further allocations construct the reported failure. Each allocation uses the explicit selected context and the ordinary region service; implementations may not summarize a source/provider callback or perform an unmodeled hidden query. The control graph must conservatively represent every feasible prefix and allocation, including refusal and reentry, with the host reservation and copied snapshot protected until commit or rollback. A failed pre-commit receive construction restores the queue entry; a terminal failure after send acceptance retains that delivery and its support. An alternative adapter representation is acceptable only if it exposes the same actual control to the independent analysis.

The sealed host send/receive transition itself does not capture or transfer an Ash continuation and is nonblocking. This fact is provisional during source inference and may grant product permission only after independent linked Core validation reconstructs the exact canonical callable, operation, context child, operand and all incoming authority paths. Ordinary selected allocation handlers, providers and their effects retain their existing capture semantics. A forged structural node, another same-typed callable, a raw IO request, unknown evidence, or an unsupported graph grants no such fact. Control emission remains inaccessible until the separately checked driver and codec contract is implemented.

## Runtime and validation obligations

At execution, evaluate the explicit context once and then the parameter projection in the specified order. Check the actual worker activation and side before transport access. Send charges and copies before acceptance; after acceptance, a later result-allocation failure must not retract the delivery. Receive reserves the FIFO head, charges before its host snapshot, and builds the complete receiver-owned result in the selected region before committing removal. The reserved head remains protected through any allocator control. Reserve an identity-bound receiver-held obligation before that commit; on refusal, restore the head and remove the unpublished reservation. Keep committed obligations with the worker exit and network owner until checked actual processing, callback and cleanup completion; a queue count, End, host flag or worker return alone is not the one-way cut proof. The owner must retain those obligations on normal return and on runtime or teardown failure. An unknown carrier outcome or panic cannot be treated as a successful drain or allow backing release.

The independent validator must authenticate all structural calls against their actual linked canonical wrapper and selected evidence, check unique ownership/incoming edges where required, reconstruct operation ports and every result/allocator path, and run ordinary graph, lexical, type, row and capture validation. The complete checked result is published only after all passes succeed under the shared cumulative budget. Missing linked evidence and unsupported restored or transformed graphs reject until their independent reconstruction is implemented. Work exhaustion or any partial result grants no permission. The retained worker/channel proof must correspond to the actual prepare, reserve, copy, commit, receiver-held, failure and settlement transitions; the C3-based one-way cut requires its own proof and actual-Core correspondence.

Focused evidence must include a real worker send and receive under a nested selected region, actual cleanup of that region, copied bytes and FIFO order, full and terminal outcomes, snapshot and allocation failure before commit, accepted-send result failure, forged operation/body/context/incoming edges, direct source and Core request rejection, cumulative-budget refusal, and nonreentrant or unsupported provider cases. The full owner joint commit, genuine End, checked processing cut, worker completion and backing settlement remain separate N2 gates.
