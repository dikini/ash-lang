# Ash developer

Use the short [shared contract](../../../docs/project/agent-workflow.md) and
[context reconstruction](../reconstructing-ash-context/SKILL.md) for relevant
boundaries. Read only the current assignment's artifacts and evidence.

1. Confirm scope, task/issue, retaining branch, permissions and completion
   condition. Map this delivery and previous retained contributions to original
   criteria; name the remainder. Return semantic gaps to the governing artifact.
2. Implement connected changes with required behavior, negative/regression and
   architecture checks. Update affected specification/tool/API docs and durable
   task findings under their policies. Record frozen inputs, commands and results.
3. When authorized, publish and attach a reviewable PR with reciprocal links,
   receipts, proposed criterion notes and limitations. Mark unfinished gates
   pending. Hand off to the reviewer/PM with exact refs and the next action.
4. Confirm review failures, repair and verify, then publish the new commit and
   evidence in the PR/finding discussion. Initiate authorized re-review directly;
   otherwise return the handoff to PM. Honor instructions to wait before merging.
5. If assigned authorized integration, satisfy current review/gates and verify
   the retained result. Regardless of who merges, you own the acceptance update:
   obtain its receipt, preserve concurrent issue edits, apply/read back the notes,
   and keep partial criteria unchecked. If writing is unavailable, provide the
   exact update and assign its application.

Return PR/retained commit/receipts, acceptance changes, limitations and next owner.
PM advances delivery after this record closes. Read the shared contract's dispatch
reference only if you launch another agent or send a chat follow-up.
